# Integration and acceptance

Rule: a check counts only if it was run on the stated commit and its output is recorded (STATUS evidence or a file under `agent_output/reports/`, which is git-ignored, plus a one-line summary in STATUS). Mocks and fixtures are labelled as such. A test that was not run is not a passing test.

## 4. Benchmark and submission gates

- Template-path and LLM-path results are reported separately. Gold `inputs` results are labelled "tool-level".
- Every run report names: commit, profile, model and prompt version (LLM path), data hash, date, per-kind correct/total, errors, wall time, tokens and cost.
- Never edit expected answers, never weaken the scorer, never hand-label test answers, never load `questions*.jsonl` answers or `inputs` in the inference path (Lenard adds a test that imports `bench.agent` and asserts it never opens `questions` files: monkeypatch `open`/`Path.read_text` during `answer()`).
- The Sunday building: run immediately; validate the output against the provisional schema; if the organizers' schema differs, change only `bench/run_benchmark.py`, rerun, revalidate.

**Submission checklist** (captain owns the upload; each line has an owner)
- [ ] `submissions/test_answers.csv` validated (Lenard)

## 5. Recovery and reconnect checks (M02/C02)

| Case | Expected |
|---|---|
| WebSocket drops during a tour | auto-reconnect 0.5–5 s; refetch snapshot and tour; banner if changed |
| Stale reroute response arrives after a newer one | ignored (revision/request_id) |
| `commit_edit` sent twice (voice repeat) | one event, same `event_id` returned |
| Preview older than the current version | `version_conflict`, new preview |
| Server restart (Railway redeploy) | sessions, tours, events persist; clients reconnect |
| Voice token failure | text chat shown, no dead button |
| Camera denied / XR unsupported | 2D map, clear message |
| Phone reload mid-tour | resumes at next pending stop |

## 6. Definitions

**Ready (a task may start):** its contract section exists at a version; required fixtures or a contract example exist; dependencies named in the milestone file are pushed or explicitly mocked with a replacement step.

**Done (a milestone is complete):** acceptance commands run on the pushed SHA with recorded output; contracts unchanged or changed through a CR; STATUS updated; mocks introduced are listed with their replacement owner; the captain has merged it or it is waiting in the merge queue with no known failure.

**Honest release report (Manuel's codex writes it Sunday 12:00 CET in STATUS):** what works on the release SHA (with evidence), what is simulated, what was cut, measured benchmark numbers, known risks.
